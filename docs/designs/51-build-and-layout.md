# Build system and code layout

**Status:** Built. The source tree is flat and wants folders (open).

## Build system

- **One top-level `CMakeLists.txt`, logic in modules in `scripts/cmake/`:** `assets`, `dependencies`, `executables`, `options`, `output`, `platform`, `targets`, `tests`, `deploy_libraries`. Source and asset folders stay clean. An included `.cmake` runs at once and can also define functions called later. Rejected: a `CMakeLists.txt` per subdirectory.
- **Dependencies:** Xerces-C, exprtk, SFML 3, Raylib, GLFW + system OpenGL, SDL2 (+ SDL2_image, SDL2_ttf), TinyXML2, PugiXML, RapidXML, lunasvg, Catch2 (tests), Qt 6 (xgegui; found only), libxml2 and libxslt (`xgecli --generate`; found only, `xge_link_xslt()` in `targets.cmake` defines `XGE_WITH_XSLT` 1 or 0, and without them xgecli says so when asked to generate). Each is found (vcpkg or system) or fetched with FetchContent; `FORCE_LOCAL_<NAME>` forces a fetched copy. One macro, `xge_dependency()` in `dependencies.cmake`, does the looking, the status line and the fetch for all of them (a call per library: its name, `WHEN` the backend is built, `PACKAGE` or `HEADER` to find it with, the repo and tag, any cache settings its fetched copy needs, and `BROUGHT_BY` for GLFW, which a fetched raylib builds itself; with no repo it only finds, which is OpenGL, `REQUIRED` and so an error when the OpenGL backend is on and it is missing, and Qt, which only leaves out `xgegui`); before it, the same shape was written out twelve times. A library is reported by name and, when its package says one, version (`Found TinyXML2 10.0.0`, the way CMake words its own messages; the copy found can be older than the tag pinned for a fetched one, which is what the version is there to show) and not by where it was found: the variable that says where is a different one for each (a package's `_DIR`, Xerces' include folder, OpenGL's first library, exprtk's header path) and handling them all was most of the macro. Only the ones for the backends that are built are looked for (next bullet). `BUILD_TESTING` is off by default.
- **Warnings (2026-10-05):** the aim is every warning that can be made to come out clean for this project's code, and none from anyone else's. What was wrong: the fetched exprtk was given `-w` ("silence third-party warnings") on its *interface*, which every target that links it inherits, so on GCC and Clang the engine's own code was compiled with warnings off; on MSVC `/W4` came later and won, so exprtk's headers still reported. Looked at: silence each library by name (what was done, and leaked); mark third-party headers as system headers and silence third-party builds separately; `-Werror`. **Chosen:** (1) `xge_warnings()` (platform.cmake) gives `xgelib`, `xgecli`, `xgegui` and `xgetest` one strict set, which replaces three copies of two flags: GCC and Clang get all, extra, pedantic, shadow, conversion, sign-conversion, old-style-cast, non-virtual-dtor, overloaded-virtual, cast-align, null-dereference, format=2, fall-through, misleading-indentation, and GCC also double-promotion, duplicated conditions and branches, logical-op and useless-cast; MSVC gets `/W4` and the common extra set (`/w14242` and friends). (2) A library that is found is an imported target, so its headers are system headers; a fetched one is declared `SYSTEM`, so they are too, and the exprtk found by `find_path` is added with `SYSTEM`. (3) A fetched library's own sources are compiled with `-w` (every target in its directory tree), so building SFML or SDL2 from source reports nothing either. The tree was brought to zero warnings under that set with GCC 13 (all backends, tests, and a default build with the Qt app) and Clang 18 (the library, command line and tests, syntax only), 22 in the engine and tests and 15 in the Qt app, nearly all a constructor parameter named like the member it initialises (`Vector2f(float x, float y) : x(x), y(y)`), the rest sign and float conversions: no behaviour changed. `-Werror` was not turned on: a new compiler or library should not break the build for a user. Not done: GCC's `-Wdouble-promotion` is GCC only because Clang's version fires on every float passed to `Catch::Approx(double)`; MSVC's `/W0` is only given to the libraries that were already silenced (xerces-c, lunasvg, plutovg), because MSVC prints D9025 when a library that sets its own `/W` level is given a second one (SFML does); and the MSVC extra set and the system-header handling were not built on MSVC by the agent that wrote them: the first warnings you see there are the thing to look at. exprtk's code-generation warning C4702 is not covered by `/external` and is still turned off by the pragma around its `#include` in `game_expr.h`.
- **Which backends are built (2026-10-05):** all eight were built always, so a plain `cmake -B build` found or fetched and compiled SDL2, raylib, GLFW, three more XML libraries and SFML's network module (which brings a TLS library and libssh2, and which nothing in the engine uses) to run one game. Looked at: all always (the old way); one of each by default with the rest opt-in; one of each with the rest chosen at run time from plug-in libraries. **Chosen:** one of each by default, SFML 3 for window and sound and Xerces for XML, the others opt-in per backend (`XGE_WITH_<NAME>`) or all at once (`XGE_ALL_BACKENDS`), and `BUILD_TESTING` implies all of them because the tests play every game through every backend and compare. The OpenGL window loads its pictures and draws its text with SDL2_image and SDL2_ttf (`window_opengl.cpp`), so turning it on brings SDL2's libraries with it (`XGE_NEEDS_SDL2` in `options.cmake`), though not the SDL2 window and sound backend, and nothing but a build with OpenGL on and SDL2 off shows it wrong: the test build has both. The enums and the factories stay complete; only the library is absent, and asking for it is an error that lists what there is. The command line and the Qt app list only what is built, so a default build's dropdowns have one entry each. SFML's network module is dropped for everyone. Plug-in libraries were not worth it for four small wrappers. TinyXML2 10 and 11 both work (the wrapper compiles clean and the suite passes against each), and `find_package` is given no version because its package is `SameMajorVersion`: a number refuses the other major and a range across both refuses everything. **Open:** the all-backends build links SFML's and raylib's sound libraries (and both image loaders) into one program, and on Linux a static build fails with duplicate symbols (the notes); a default build is not affected. Nothing builds the default configuration automatically, so a change to the `#ifdef`s needs a build with no options as well as with tests. Shell scripts install prerequisites for apt, dnf, pacman. C++20 (`cxx_std_20`).
- **`output/` layout:** programs, copies of `games/`, `assets/` and `xgedef.xsd`, and `libraries/` (DLLs, or `.so` on Linux, and Qt plug-ins) go in `output/Debug` or `output/Release` (ignored by git). `output.cmake` sets `CMAKE_RUNTIME_OUTPUT_DIRECTORY` and `CMAKE_LIBRARY_OUTPUT_DIRECTORY` to `output/$<CONFIG>/libraries` before any target exists (so fetched dependencies follow); `xge_place_program()` moves each program up; the generator expression stops Visual Studio / Ninja Multi-Config adding a config folder of their own; `assets.cmake` copies into the same path; `platform.cmake` points SFML and Xerces back at `libraries/`. A single-config build with no `CMAKE_BUILD_TYPE` becomes Debug. Static libs and import `.lib`s stay in the build directory.
- **DLLs in `libraries/` on Windows:** Windows loads a program's DLLs before `main()` from its own folder, system folders and `PATH`; delay-loading is out (Qt and SFML export data). Chosen: a private assembly. Each program embeds a manifest (MSVC links `xge_libraries.manifest`, made by `output.cmake`) that needs the assembly `libraries`; Windows finds `libraries/libraries.manifest`; every DLL listed there loads from `libraries/`, for the whole process (built and run on Windows with Visual Studio and vcpkg). On Linux and macOS the programs carry a relative run path (`$ORIGIN/libraries`), so a copied `output/<config>` still runs. After each build `deploy_libraries.cmake` moves the DLLs vcpkg copied next to the program (vcpkg follows each DLL's imports) into `libraries/` and writes the list from the folder, under a lock because the programs build in parallel. Qt: `windeployqt` through `Qt6::windeployqt` (vcpkg points it at the `.debug.bat` in Debug; the plain tool fails on debug builds; needs `qtbase[windeployqt]`), plug-ins in `libraries/plugins`, a `qt.conf` beside the program.
- **Gotchas:**
  - On Windows, SFML fetched from GitHub with FreeType from vcpkg can leave a malformed `optimized`/`debug` entry in FreeType's `INTERFACE_LINK_LIBRARIES`; `platform.cmake` strips them where consumed. Untried: `CMAKE_DISABLE_FIND_PACKAGE_Freetype`.
  - Fetching both SFML and raylib static (no vcpkg, no system packages) fails to link on Linux with duplicate `stbi_*` (and miniaudio) symbols; vcpkg DLLs do not. Building one as shared avoids it; not done.
  - vcpkg's raylib 6.0 is configured with `CUSTOMIZE_BUILD=ON`, which turns on every optional feature (`SUPPORT_CUSTOM_FRAME_CONTROL`, JPEG for `assets/paddle.jpg`). A raylib built another way may not load Pong's paddles; the backend then throws.
  - A CMake target named `m` collides with plutovg's `-lm`.


## Code layout and pipeline

- The description is treated like a program with a front end: **parse, validate, evaluate, (generate)**. An explicit validation stage makes it easy to see a bug in one stage leaking into another. The code has this shape: `game_xml` parses and validates, `game_expr` evaluates into `Object`s and `State`s; generating is a separate path, XSLT on the game file run by `xgecli --generate` ([generator](40-generator.md#generating-a-program-with-xslt)), and does not go through the loader.
- A July 2026 skeleton (empty files, branch `rewrite`, retired 2026-09-30) layered `core/engine` (loop phases input/update/render, a `system_*` tier under a `service_*` tier), `core/game` (`compile_*`, `model_*`), `window`, `xml`. Too layered for the code that existed; the tree was flattened into `lib/source` and `lib/include` with the same responsibilities. Keep its good ideas: three loop phases so update can run without a window; `model_object` and `model_states` are parallel definitions; what is genuinely runtime is the current state and live objects.
- **Open:** `lib/` is flat and growing (31 source and 32 header files). Group by responsibility: game loading and evaluation, engine loop, collision and commands, window backends, audio backends, XML backends. Visual Studio filters are built from directories, so this is only the layout on disk. Also open: a configuration service, whether a "live snapshot" (current state plus live objects) is its own type, rename `collisionData.basic` (a leftover of the old `basic="basic"` spelling).
- Second-batch ideas: construct the game in one step (parse, validate, evaluate; no object on failure; keep the constructor small by delegating to a builder); resolve verb names to handlers once at load so the running game never looks up strings ([ideas](57-ideas.md)); phase order input, update, collisions, render.
