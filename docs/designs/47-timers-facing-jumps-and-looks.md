# 47. Timers, facing, jumps, looks and key sets

**Status:** built (`tests/test_gameplay_verbs.cpp`, `games/kaboom.xml`, `games/frostbite.xml`, enemy fire in `games/spaceinvaders.xml`, `games/spaceinvaders2.xml`, `games/demonattack.xml`, `games/berserk.xml`); new tags: `<timers>` (with `<timer>`, `<every>`, `<after>`) on objects, groups and states, `<facing>`, `<jump>` (with `<distance>`, `<seconds>`), `<reverse />`, `<become>`, `<reveal>`, `sprite=` on a collision rule, `<keys>` sets in `<states>` and `keys=` on `<inputs>`, several keys in one `button=`

## Why

A read of every shipped game (2026-10-03) found the same workarounds again and again, all standing in for something the language could not say:

- **No clock.** Frostbite's cold was a one-pixel object, coloured like the sky, crossing the screen once a second so that its edge rule could take a degree. Freeway and Space Race gave up their timed rounds. No enemy could fire back (Space Invaders, Demon Attack, Depth Charge), and Kaboom's bomber was decoration, because nothing happens unless a key, a touch or a condition makes it.
- **No facing.** Berserk's man walks four ways and could only shoot up; only an object with a `<heading>` fired any other way, and a heading turns the picture.
- **No look that changes.** Frogger fills a home by putting a frog under each lily pad and having the pad `<die />`. Frostbite could not be written at all: its rows of ice turn blue when landed on, and its igloo grows a block at a time.
- **Copied key bindings.** Every play state of a game bound A and Left, D and Right, one by one, and a game with waves (Kaboom) or rooms (Berserk) bound them all again in each state.
- **Commands a context quietly ignored.** `<inc>` and `<dec>` in a condition, and `<reset object>` in a collision, were accepted by the schema and did nothing ([44](44-games-written-by-another-ai.md)). Kaboom kept an invisible object, `tally`, only so a condition could do the reset a collision could not.

The author asked for a timer (something that fires and puts events in the queue, and a way to know how much time has passed), enemies that fire back, a reworked Kaboom with the bomber dropping the bombs, reusable named key sets that a state can override, facing for a four-way shooter, a simple jump, and a Frostbite rewritten with the shore and igloo at the top and floes below. Looks and `<reveal>` were added because the rewritten Frostbite needed them.

## Decisions

- **Timers are commands on a schedule, in the places that already hold commands.** An object's `<timers>` and a state's `<timers>` hold `<timer>`s: an `<every>` or an `<after>` (seconds, a value) and then commands. An object's count while it is shown and in play, a state's while it is current, the same rule animations use, so a pause, a menu or a dead enemy stops them with no extra words. The alternative of a global event queue with named events and handlers was the larger idea floated; it is a second way to say "when X, do Y" next to rules and conditions, so the smaller form went first.
- **The interval is worked out again each round, after the commands run.** `<every><random min="1" max="3" /></every>` waits a new time each round, which is what makes a bomber or an invader unpredictable without any AI, and an expression can follow a variable that the timer's own commands change (a rate that speeds up). Expressions now see object variables as they change (they were frozen at load), which this needed.
- **"How much time has passed" is a timer counting a variable.** A timer that `<inc>`s a variable, shown by a bound `<number>` and tested by a condition, is a visible clock built from parts the language has; a separate time value in expressions was not added.
- **Frames, not wall time.** Seconds are turned into frames with the window's `<framerate>`, like animation intervals ([42](42-bitmap-sprites-and-animation.md)); the engine has no clock, and a game that slows down slows down evenly.
- **Facing is four directions, not a heading.** `<facing>` follows the last move, hop or jump and never turns the picture; `<fire>` leaves the middle of that side at the projectile's own speed. An object without one fires as before (from its top, at the projectile's own velocity), so nothing shipped changed by accident. Space Invaders' cannon simply has no facing: it always fires up.
- **Enemies fire with the same `<fire>` and pools.** An enemy is a shooter with a facing and a timer; its shots are a pool (a hidden `<group>`), which also caps how many are in flight, as the arcade games did. No aiming yet.
- **A jump is a straight, timed move through the air.** `<jump direction="down"><distance>` over `<seconds>`: the object touches nothing while airborne and meets what it lands on, which is exactly Frostbite's "land on the ice or in the water". A jump that would land off the screen is not made, so "up" from the top row is simply nothing. The arcing, gravity-driven jump planned in [13](13-verb-vocabulary.md) and [23](23-jump-and-air-control.md) is still to come; this one has no arc and no air control.
- **Looks are named sprites, and a look is also a state.** Several named sprites and no animation are looks; `<become sprite>` switches the object, or with `object=` a whole group, and a reset shows the first. A collision rule with `sprite="white"` runs only while its object shows that look, which is how a row of ice gives one block and then no more until it is white again. Making the look the state, rather than adding per-object state variables or changing an object's class, keeps it visible: what the player sees is what the rule tests.
- **`<reveal>` beside `<release>`.** `<release>` puts pool members in the middle of the object running it (rocks breaking); `<reveal>` puts them back where they started, which is what an igloo built a block at a time, a door that appears, or a fish that comes back need. Show and hide verbs were the earlier idea ([21](21-frogger.md)); `<reveal>` and `<die />` are that pair, in the pool form the engine already had.
- **Commands work where they make sense, not where they happened to be wired.** Conditions and keys now run `<inc>`, `<dec>`, `<become>` and `<reveal>`; collisions run `<reset object>`, `<reverse />`, `<become>` and `<reveal>`; an action can do a bare `<reset />` (the object back where it started), so a condition can send the player home through a `<trigger>`. Kaboom's tally and Frostbite's clock object are gone.
- **Key sets are named bindings with overrides.** A `<keys name>` set at the top of `<states>` holds `<input>`s; `<inputs keys="name">` takes it and the state's own `<input>`s go over it, key by key, as the author asked. One `button=` can name several keys (`"a left"`), so W, A, S, D and the arrows are one line each.

## The games

- **Kaboom** was reworked to the arcade game: the Mad Bomber paces the rooftop, turns on a timer with a random wait, and drops a bomb from a pool under himself on another timer. Because the bombs leave from wherever he is, they come in trails and clusters that follow him, which is what makes it playable. A bomb on the ground does `<reset object="bombsN" />`, every falling bomb at once. A test plays the first wave with an automatic player that follows the lowest bomb and checks that it gets through with buckets to spare.
- **Frostbite** was rewritten: a snowy shore with the igloo along the top, four rows of floes drifting in alternating directions below, Bailey jumping between them. A white row landed on turns blue and adds a block; four blue rows turn white again; the water drowns him unless he is on a floe; the cold takes a degree a second; snow geese push him along (`<carry />`), off the ice if he is slow; a fish is a bonus that comes back on a timer; the finished igloo opens its door, and walking in wins.
- **Space Invaders** (both) and **Demon Attack**: the aliens face down and fire from a pool after random waits; the cannon has three lives. The aliens' catch-all rule (`<collision><die /></collision>`, which would have let their own bombs kill them) now names the cannon's bullet.
- **Berserk**: the man faces the way he walks and shoots that way; the robots fire; the walls kill, as in the arcade game (the AI-written `<stick />` against an object did nothing); the two rooms share one key set. (Rewritten again on 2026-10-04, [48](48-berserk.md).)

## Options considered

- **A global event queue** with named events, raised by rules and timers and handled in states. More general, and the likely next step if timers and conditions start chaining; for now every event in the shipped games is "after a while" or "when this touches that".
- **A time variable in expressions** (`time.seconds`). Expressions are worked out once at load except a timer's interval, so it would have read the load time almost everywhere.
- **Facing as a heading in 90 degree steps.** That would turn the picture, which a four-way sprite drawn for each direction might want later, but a single sprite does not.
- **Class changes instead of looks** (`<become class="blueice">`): rules already filter by class, but what changes would not be visible, and the floe's colour would need its own command anyway.
- **One row of ice as one wide object** with pixel collisions: a whole row would turn blue by itself, but it wraps as one block with a big gap.

## Not done

Aiming (an enemy firing toward the player), only the front invader of a column firing, an arcing jump, looks combined with an animation or a heading, a timer's time left shown on screen, an event queue, mutable game-wide variables (an object's own variables, which every rule can name and texts can show, did the job in every game here), and `<goto state>` (a push that replaces the current state: Kaboom's waves and Berserk's rooms still push, so the stack grows by one each time, which a reset clears).
