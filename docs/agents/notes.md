## What exists

- `docs/readme.md`: the engine as it works now. Update it whenever a verb, attribute or file changes.
- `docs/designs/00-designs.md`: index of design topics with options and status. One file per topic, numbered `NN-name.md`. Keep the table and the files in step.
- `docs/agents/sources.md`: which conversations fed which design entry.
- `docs/agents/scan_export.py`: ranks and dumps conversations from a Claude chat export.
- `docs/agents/scan_chatgpt_export.py`: the same for a ChatGPT export (many `conversations-NNN.json` files; keys are `file:position`).

## Conventions the author asked for

- C++ files start with a header comment: filename, "XML Game Engine", "author: beefviper", and the date, in the form used by the existing files.
- Files end with exactly one trailing newline.
- Direct answers and clear pushback are preferred over hedging.

## Facts that are easy to get wrong

- Key conventions for `games/`: Space starts, pauses and plays again (never Enter); player one is W/A/S/D. Where Space fires, pause is P or Escape. Keep new games to this.

- The root `readme.md` is a short overview (games, format, build, status); the detailed description is `docs/readme.md`. Update both when a verb, a game or a dependency changes.
- The repo has three branches: `master`, `rewrite`, `claude`. The active engine described in these docs is on `claude`.
- Function-call syntax is gone: attributes only name or pick things, everything else is element content ([design 03](../designs/03-expression-syntax.md)). Arithmetic in values is still exprtk text.
- No handle system and no `Value` variant exist yet, despite being decided or discussed ([07](../designs/07-object-variables-and-references.md), [08](../designs/08-entity-storage-and-handles.md)). Swept collision is built ([11](../designs/11-collision-detection-and-response.md)).
- `CollisionDetector::circleRectangle` was rewritten (nearest point on the rectangle, and the closest side for a centre inside it); `tests/test_collision_geometry.cpp` pins it. Add a test there before changing it.
- The XSD checks structure, not expression text; `xsd_lite` (used by the three non-Xerces backends) covers only the XSD subset the schema uses, and `tests/test_xml_format.cpp` pins what both validators must reject.
- Files in the repo use CRLF line endings on disk (`.gitattributes` stores LF and checks out CRLF); keep them when editing. A few newer files (design 22 to 28, `scan_chatgpt_export.py`, `sources.md`) are LF on disk; git normalizes them on commit.
- Every cell of a `<grid>` has its own name (`aliens.3.2`, column then row from 1), so a single cell can be addressed; the grid's name still means the whole grid.
- The engine's internal list of unfiltered and filtered object-against-object collision rules is still called `basic` (`collisionData.basic`), a leftover of the old `basic="basic"` spelling; the XML no longer has it.
- Backends are selected in C++ by constructor arguments, on the command line by `-w`/`--window`, `-x`/`--xml` and `-a`/`--audio` ([37](../designs/37-command-line.md)), and in `XGEGUI` by its Options dialog, which can also change the video or sound library of a running game ([39](../designs/39-opengl-backend-and-options.md), [45](../designs/45-sound.md)).
- Timers count frames (`Game::framesFor`, seconds times `<framerate>`); a repeating timer works its interval out again on the frame after it goes off (`framesLeft = -1`), so its own commands can change it. Object timers count only while `isShown`; state timers live in `Game::stateTimers` by state name, because the state stack holds copies. Expressions read object variables live now: `Game::refreshBoundTexts` also writes `expr.objectVariables`, so anything that changes a variable should go through it.
- An object in the middle of a `<jump>` (`Object::isAirborne()`) is left out of every collision pair and of `unless=`; it lands in `Game::applyHops`, and the landing frame counts as moving so it meets what it landed on. Tests that build a `Game` without an `Engine` must call `setCurrentState(0)` and measure sizes (`measureShapeSize`) themselves, or nothing is shown and every size is 0.
- Lines, `<bitmap>`s and `<svg>`s are built by one block of `game_expr::buildSpriteParams`: read, draw into a `Bitmap`, `flipBitmap` (bitmap and svg), then keep a `Turnable` for an object with a heading. A turned picture is a square big enough for any angle, so a flip is not done by turning. Keep new picture kinds on that path rather than adding drawing to a window backend.
- Several named sprites and no animation are an object's looks (`Object::looks`, `showLook`, `showLookNamed`); a look is spriteParams plus a bitmap, swapped in and marked dirty, so no window backend changed. A rule's `sprite=` reads `lookName()`.
- Sound: `Game` never touches audio. `<play>` queues a name (`Game::requestSound`, once per name per frame) and `Engine::step()` plays the queue on its `Audio` at the end of the frame; tests read `Game::takeSoundRequests()` or give `Engine` a recording `Audio`. `Engine(game, window)` with no audio is `NullAudio`, so tests never open a sound device. A sound library that cannot start is a warning and silence, not an error (unlike a window). The samples come from `synthesize()` (`sound.h`), never from a library, so every backend sounds the same.
- SDL is shared by `SDL2Window` (video) and `SDL2Audio` (audio): each starts and stops only its own subsystem, and whichever finishes last calls `SDL_Quit()`. Do not put a bare `SDL_Quit()` back in either, or closing one stops the other.
- SFML 3 and raylib both carry miniaudio (as well as `stb_image`, see step 8 below); with both built static from source the link may meet duplicate symbols. The agent's Linux build installed both as shared libraries, which avoids it; vcpkg's DLLs do too.
- Raylib backend: raylib has no event queue; `EndDrawing()` reads the keyboard and the close button itself, once a frame. `RaylibWindow::pollEvents()` must not call `PollInputEvents()` too (that reset what `EndDrawing()` had just read, so every key press and close request was lost) and reports key changes by comparing `IsKeyDown` with the last call. Escape is not raylib's exit key here (`SetExitKey(KEY_NULL)`). Some raylib builds (the author's Windows build, raylib 6.0) are compiled with `SUPPORT_CUSTOM_FRAME_CONTROL`, which makes `EndDrawing()` skip the buffer swap, the polling and the frame wait (a blank, "Not Responding" window); `RaylibWindow::display()` notices this once (`GetFrameTime()` is still 0 after `EndDrawing()`) and does those three steps itself. Anything drawn into a render texture with `DrawTexture` must stay alive until `EndTextureMode()`, which is when raylib draws its batch (unloading it first drew nothing, so no sprite of lines showed).
- The engine is a library (`XGELIB`, in `lib/`); `cli/` is XGECLI (the command line program) and `gui/` is XGEGUI (the Qt application, [38](../designs/38-qt-front-end.md)); each has its own `source/` and `include/`. Targets: `XGELIB`, `XGECLI`, `XGEGUI`, `XGETEST` (tests) and `XGEDATA` (copies games and assets). New engine source files go in `ENGINE_SOURCES` in the top-level `CMakeLists.txt`; tests link the library, so they no longer need that list. Static by default, `XGE_BUILD_SHARED` for shared ([35](../designs/35-library-and-front-ends.md)).
- Every `Window` backend opens a window of its own (`WindowFactory::create(desc, backend)`), and throws `std::runtime_error` if the library cannot start. Never destroy a library's window after creating the next one: raylib and GLFW can only have one (`Engine::replaceWindow` destroys first). A front end that pauses the game but keeps a library's window calls `Engine::pump()` so the window stays responsive; it does not run the simulation, and keeps the keys it reads for the next `step()`.
- `XGEGUI` uses no OpenGL through Qt: `GameView` is an ordinary widget. A `QOpenGLWidget` and a library's OpenGL context on the one thread draw into each other (Qt trusts its own record of the current context), and a window that once held a `QOpenGLWidget` seemed to stay broken after a library had run; see [40](../designs/40-split-windows-in-xgegui.md). Do not bring one back without a guard around every call into a library.
- Anything in `XGEGUI` that can run while `GameSession` swaps the game or its window (a Qt signal from a focus change, a timer) must check `GameSession`'s `changing` guard, as step, reset and redraw do: for part of a swap the engine has no window.
- Library code throws, it never calls `exit()`: `XGEGUI` loads one game after another and has to survive a bad one. `XGECLI` catches and prints.
- Text falls back to a font stored in the program (`lib/source/builtin_font.cpp`, 8x8, public domain) when `assets/tuffy.ttf` cannot be found; the assets are looked for relative to the working directory, so `XGECLI` and `XGEGUI` first make the folder holding `games/` and `assets/` the working directory (`lib/source/data_folder.cpp`: working directory, program folder, the one above); a program that skips that falls back to the built-in font ([36](../designs/36-builtin-font.md)).
- A new game file has to be added to `data_xml` in `scripts/cmake/assets.cmake`, or the build does not copy it into `output/<config>/games/`; a new test file has to be added to the list in `scripts/cmake/tests.cmake`.
- Frogger's board is built from many named rectangles, drawn in file order (so scenery first, the frog last); its lanes, pads, homes and hedges are `<group>`s, read as one object per member (`logrow3.2`, `pads.1`), and Space Race's debris lanes the same way. The tests address members by those names. See [21](../designs/21-frogger.md) and [29](../designs/29-groups.md).
- `ShapeKind::Line` now means any picture the engine draws itself: `<line>` and `<bitmap>` sprites both become a `Bitmap`, with spriteParams `{"line", w, h}`, so no window backend knows the difference. The XGEGUI inspector calls such a sprite "drawn" / "pixels"; that edit was not compiled (no Qt on the agent).
- `tests/invaders_fixture.h` holds a frozen copy of the old Space Invaders XML; the win, swept-collision and lockstep tests use it, so redrawing `games/spaceinvaders.xml` does not break them. Space Invaders itself is tested in `tests/test_bitmap_sprites.cpp`.
- `<fire>` centres the projectile on the shooter's top edge (a thin bullet leaves the middle of the gun); Depth Charge and Astrosmash tests expect that.
- Animation is counted in frames (`seconds * framerate`) by `Object::advanceAnimation`, called for every shown object at the top of `Game::updateObjects`. A `<bitmap>` on an object with a `<heading>` is drawn once and kept; an object that turns keeps a shared `Turnable` (the lines or the original picture, one per animation frame in `Object::turnables`) and its one current `bitmap`, redrawn by `Object::showHeading` only when the heading rounded to a whole degree changes (360 headings; `turnBitmap`, `rasterizeTurned`). Letting each backend rotate a texture was rejected: the drawn and the collision-tested pixels would differ between libraries.
- `<svg>` sprites (Claude, Sonnet 5.5, 2026-10-02; [design 43](../designs/43-svg-sprites.md)) are drawn once at load by `rasterizeSvg` (`lib/source/svg.cpp`, lunasvg v3.5.0, linked `PRIVATE`; only `svg.cpp` includes it) into the same `Bitmap` as a `<line>` or `<bitmap>`, so no backend changed. `games/spaceinvaders2.xml` uses `assets/Space Invaders Color Sprites.svg` (6 by 4 cells of 32 units; the sheet's `backdrop` group is left out with `<hide>`). New game and asset files are in `assets.cmake`; the tests are `tests/test_svg_sprites.cpp`. The file name of the sheet has spaces in it, which CMake copes with when it is quoted, as `assets.cmake` does.
- The SVG tests and everything else but the window backends and `XGECLI`/`engine_input` tests were built and run on Linux with a reduced build (engine sources without the four window backends and a stub `WindowFactory::create`, system Xerces, TinyXML2, PugiXML, RapidXML and Catch2 3.4, exprtk from GitHub, lunasvg built from its tag). Nothing was built on Windows or with the real CMake configure of the whole project: the CMake changes (`dependencies.cmake`, `targets.cmake`, `options.cmake`, `assets.cmake`, `tests.cmake`, `platform.cmake`) were checked only by a small FetchContent project that links lunasvg `PRIVATE` into a static library. Watch the first real configure. A CMake target called `m` collides with plutovg's `-lm`; the project has none.
- `Kaboom`'s "a game left running eventually brings bombs down on a moving bucket" (`tests/test_kaboom.cpp`) failed once in the one full run and passed on every rerun, including with the failing run's seed (it is random in a way Catch2's seed does not control); it has nothing to do with sprites.
- XGEGUI's look is `gui/source/theme.cpp` (Fusion style plus a palette-derived style sheet; [design 38](../designs/38-qt-front-end.md)). Do not style `QSpinBox` borders in the sheet: the arrows disappear. The tree has `setAlternatingRowColors(true)` and bold top-level rows in `inspector.cpp`.
- On Windows the repo's `.gitattributes` converts line endings on commit; git prints LF-to-CRLF warnings, which are harmless.
